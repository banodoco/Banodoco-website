# Wave 2 / S4 — cross-wave synthesis and next evidence wave

Base: `1fa145fc51e89c8a1788db39aff98e775a576073`

Scope: synthesis of Wave 1 L1–L10 and Wave 2 S1–S3. This report changes neither application code nor the frozen North Star.

## Executive judgment

The architecture is not generally unsound and does not warrant a rewrite. It has a coherent central path—one composition root, one scene, one virtual journey coordinate, schema-derived chapter identity, chapter-local behavior, and a useful static application. The concentrated risk is that the otherwise traceable path relies on a few process-wide and cross-tier contracts that are either unbounded, hidden, or checked dishonestly: startup non-settlement, global clock replacement, animator registration chronology, broad mutable scene globals, inconsistent frame-failure semantics, independently authored route/content meaning, and gates that can report success without exercising the claimed browser or artifact.

The most urgent *verified* problems are incorrect HTTP Range behavior, broken no-JS static deep links, false-green browser/artifact coverage, global clock corruption, continued rendering while WebGL is lost, and the initial DPR/TAA target oversizing. The most urgent *unverified but source-supported* risk is an indefinitely pending startup: three Luna passes found the same unbounded chain, but none actually held each dependency open and observed the terminal visitor state. It must remain a P0 reproduction candidate rather than be promoted by repetition alone.

The plan remains **forming**. Wave 2 has made it much narrower, but the accepted backlog cannot be frozen until the P0 candidates are reproduced or falsified, the single-instance/fallback and static/no-JS contracts are characterized, and performance claims are correlated in comparable traces. No current evidence supports an XHARD item, a broad lifecycle framework, a generalized render scheduler, or file-size-driven decomposition.

## Evidence standard used in this synthesis

- **Verified behavior** means a report records a direct runtime, protocol, measurement, or immutable-repository observation. It may still need broader device coverage.
- **Source-proven candidate** means the control path exists deterministically in source, but the claimed visitor outcome or supported contract has not been exercised. Per `.oracle/plan.md`, this is not yet enough for a correctness backlog item whose acceptance criterion depends on runtime behavior.
- **Contract candidate** means current behavior is clear but whether it is wrong depends on an explicit support decision (for example, page-lifetime singleton versus retryable scene).
- **Hypothesis** means source suggests a cost or visual failure, but no comparable trace or capture establishes material impact.

Severity below describes consequence if exercised; confidence describes the evidence for the stated behavior; reach describes how much of the visitor/contributor system it affects. `P0–P3` are implementation-order classes from `.oracle/plan.md`, not incident labels.

## Reconciled system boundary

The supported system today is best described as **one scene and one journey for one `Document` lifetime**, with local activation/deactivation inside cards, chapters, visibility, responsive layout, and WebGL loss/restore. `main.js` composes and publishes the scene, `organism/organism.js` owns rendering, `journey/journey.js` coordinates progress and frame application, `chapter-registry.js` constructs chapter capabilities, and UI/rail consume those capabilities (`main.js:302-361,696-738,911-955,1174-1269`; `organism/organism.js:1810-1955,2069-2144`; `journey/journey.js:106-283,922-1007,1262-1271,1361-1449`; `journey/chapter-registry.js:1-41`). S1 and S2 agree that page-lifetime listeners and allocations are not automatically leaks under that contract (`wave2-S1-architecture.md`, “Actual system topology”; `wave2-S2-lifecycle-state.md`, “Lifecycle verdict”).

That contract has four true seams:

1. **Availability:** module evaluation and boot must reach either interactive activation or an accessible static handoff. Rejection is owned; non-settlement is not (`main.js:1174-1269`; `journey/lib/baked.js:73-107`; `journey/journey.js:1454-1559`).
2. **Frame ownership:** scene owns the RAF/composer; journey owns virtual progress and camera composition; chapters own local geometry; UI/rail own presentation and input surfaces. Hidden globals, monkey-patching and insertion order blur those otherwise valid boundaries (`organism/animation.js:4-38`; `journey/director.js:196-218,375-401`; `journey/ui.js:1571-1589,2718-2722`).
3. **Failure state:** startup rejection falls back, animator failure logs and continues, journey subsystem failure is permanently silenced, and render failure escapes while the next frame is already scheduled (`main.js:1256-1269`; `journey/failure-guard.js:1-11`; `organism/animation.js:13-38`). These are conflicting authorities over whether the interactive tier is still trustworthy.
4. **Tier semantics:** live, static, ownership, package and server are legitimate separate applications, but route identity, roster meaning, no-JS behavior and delivery policy are independently authored beyond the existing string-drift checks (`journey/structure.js:4-120`; `static/index.html:1685-1744,1941-1997`; `content/contributors.js:13-24,274-283`; `tools/build-static-content.mjs:3-81`).

## Agreements and contradictions resolved

1. **Startup:** L1, L3, L4, S1, S2 and S3 agree on an unbounded readiness chain. They do not supply the controlled hang required to verify the visitor outcome. Resolution: source-proven P0 candidate, not a verified hang (`wave1-L1 #1`; `wave1-L3 #1`; `wave1-L4 #1`; `wave2-S3-performance-failure.md`, “Availability failure boundary”).
2. **Malformed bake data:** L7 calls it fatal; L9 and S1 show `main.js` catches boot rejection. Resolution: fatal to the interactive tier, with a static handoff—not a blank-site outage (`wave1-L7 #1`; `wave1-L9 #1`; `main.js:1256-1269`).
3. **Responsive resize:** L4 found renderer resize order coherent; L5 found tablet/compact camera composition can remain stale. Resolution: both are true at different layers. Buffers update immediately; same-mode camera offsets are not reapplied for every mode (`organism/organism.js:1836-1849`; `main.js:213-252,721-738`; `wave2-S3-performance-failure.md`, “Responsive contradictions resolved”).
4. **Static tier:** browser smoke proves five readable sections; L2/L10 prove no-JS route parity is broken. Resolution: useful progressive content, defective deep-link destination behavior—not “static works” versus “static is useless” (`wave1-L2 #1`; `wave1-L10 #1`; `tools/browser-smoke.mjs:158-168`).
5. **Contributor authority:** L10's prose-diff count is real, but “two canonical datasets” is too simple. `CONTENT.contributors` is a 16-slot opening cast; `PERSON` is the canonical full person ledger. The defect is that static calls the slot set a complete authoritative contributor index (`content/content.js:761-810`; `content/contributors.js:13-24,274-283`; `static/index.html:1497-1507`; `wave2-S1-architecture.md`, coupling G).
6. **Context loss:** L6 verified continued composer work; L4's TAA smear remains a visual hypothesis; L7's stale timer result is synthetic and real-event reach is unknown. They are three separate claims, not one proven restoration failure (`wave1-L6 #4`; `wave1-L4 #2`; `wave1-L7 #5`).
7. **Card warming:** L6 observed mostly font warming in its window; L9/S3 prove all callbacks can launch uncancelled fetches. Resolution: idle starvation explains the observation; impact, overlap and cache reuse still require a network trace (`journey/cards/index.js:75-113`; `wave2-S3-performance-failure.md`, “Correlated cost”).
8. **Portrait loading:** late-settlement disposal guards are sound, while activation can still wait forever. Disposal safety and readiness terminality are distinct (`journey/chapters/owned/portrait-photo-loader.js:3-10`; `wave1-L3 #1 and #4`).
9. **Capture residue:** L8's claim that `_check` PNGs are universally untracked/release-blocking is false. S3 verified all ten are tracked at the base SHA. The remaining defect is that a documented read-only check writes tracked outputs and can dirty them (`tools/capture.py:847-850,899-904`; `wave2-S3-performance-failure.md`, “Test-gate honesty” #5).
10. **Recreate/teardown:** L1/L3/L4 prove module-global, non-reentrant ownership, but the shipped page constructs once. Resolution: no visitor leak is accepted under the present one-document contract. Retry/recreate work would first require a support decision and then make rollback/disposal mandatory (`journey/journey.js:106-130`; `journey/chapter-registry.js:22-41`; `journey/lens.js:288-304`; `wave2-S2-lifecycle-state.md`).

### Claims rejected or explicitly downgraded

- **No broad rewrite or “god-file” task.** File size alone does not establish a broken boundary; the current coordinator makes the frame path easier to trace in several places.
- **No universal teardown/disposal project.** Permanent page listeners, hero resources and ownership's visibility RAF are consistent with the current one-document lifetime. Disposal is required only for a supported transition or demonstrated growth plateau failure (`wave2-S2-lifecycle-state.md`).
- **No import-cycle backlog.** L1 found none in the inspected boot graph.
- **No generic card/portrait leak claim.** Cards release local media; portrait code guards late settlement. Readiness and warming concerns remain narrower.
- **No production compression defect yet.** Local `serve.py` did not encode the Three.js module, but Railway/edge headers were not observed (`wave2-S3-performance-failure.md`, “Origin/server”).
- **No restart-idempotence defect yet.** Packaging rejects a nonempty `/tmp/public`; whether Railway preserves that path across restart is a platform hypothesis.
- **No current TAA-restoration-smear finding.** History invalidation is suspicious; only first-restored-frame captures can establish the visual outcome.
- **No claim that all `_check` files are untracked or every release aborts.** S3 falsified that wording; retain only tracked-output mutation and nondeterminism.
- **No static-total-outage or two-canonical-rosters framing.** Both obscure the narrower destination and semantic-authority defects.
- **No performance optimization justified by bytes or a single call-site sample alone.** TAA sizing is the exception because the allocation error and a controlled before/after signal are already measured.
