# Wave 2 / S2 — whole-system lifecycle and mutable-state model

## Judgment

The live site is designed as **one scene and one journey per `Document`**, not as a reusable component host. That makes most permanent DOM listeners and page-lifetime GPU allocations acceptable: navigation to `/static/` or `/ownership/` destroys the document, and no live caller recreates the scene. The supported in-document lifecycle is narrower but real: prepare → activate, chapter/card activate/deactivate, visibility suspension, responsive changes, WebGL loss/restoration, and terminal fallback. Same-document recreate/retry is not evidenced as a product requirement and should not by itself justify a universal lifecycle framework.

The high-risk lifecycle defects are instead at those supported boundaries. Startup has several uncancellable, unbounded readiness gates; boot mutates the scene and installs listeners before readiness but is permanently latched and has no rollback; context loss leaves the render loop submitting work; and intro acceleration permanently replaces the realm-wide monotonic clock. These are correctness and graceful-failure issues, not cleanup aesthetics. Wave 1 evidence converges strongly on them (`.oracle/findings/wave1/wave1-L1.txt:3-11`, `wave1-L3.txt:3-9`, `wave1-L4.txt:1-5`, `wave1-L6.txt:7-13`, `wave1-L7.txt:3-12`).

## Whole-system ownership model

| Lifetime / owner | Mutable state and work | Boundary actually present |
|---|---|---|
| Module evaluation | `journeyModuleP` begins the dynamic import and baked geometry begins manifest/bin fetch immediately (`main.js:18-25`; `journey/lib/baked.js:55-57,75-107`). Card modules later schedule warming and Discord preparation at import time (`journey/cards/index.js:92-113`; `journey/cards/discord.js:457-467`). | ES-module cache for the document; no reset/cancel. |
| Hero scene | `createScene()` owns renderer, composer/TAA, controls, scene graph, named animator `Map`, and the perpetual RAF (`organism/renderer.js:15-30`; `organism/animation.js:4-47`; `organism/organism.js:1834-1849,2072-2144`). | Journey instance | `state.js` owns route/progress and a hash listener (`journey/state.js:27-30,59-81`); `scroll.js` owns virtual position, gesture/resolution state and wheel/touch/key/resize/visibility listeners (`journey/scroll.js:211-234,1668-1693`); `director.js` owns camera handoff and replaces `sceneApi.setView` (`journey/director.js:196-218`). `journey.js` owns blend/detail/activation state, composes all of these, and publishes `window.journey` only on activation (`journey/journey.js:1361-1391`). | `activate()` is idempotent, but there is no detach/destroy. `boot()` has a module latch, set before validation (`journey/journey.js:106,123-131`). |

Chapter constructors add groups/animators while being prepared (`journey/chapters/connect/index.js:406-409,793`; `journey/chapters/owned/index.js:73-76,472`; `journey/chapters/final/index.js:47-51,899`). | Chapter visibility/arming and card `activate`/`deactivate` are the normal local lifecycle. Owned exposes portrait disposal (`journey/chapters/owned/index.js:709-713`), but the journey never calls it. ### Boot and fallback state machine

The effective sequence is:

`module fetches/import` → `createScene + start RAF` → reserve the `journey` animator slot and create the lens (`main.js:350-361`) → publish `sceneApi` → prepare rail and four chapters in painted slices → `boot()` installs spine/director/scroll/UI → `state.ready` waits for portrait preparation, shader compilation, warm draws and GPU drain → `activate()` enables scroll and publishes `window.journey` (`main.js:1174-1255`; `journey/journey.js:123-190,204-273,1485-1564`).

There are useful graceful-failure pieces: scene construction failure immediately links to the static tier (`main.js:302-318`); journey failure removes intro-capture listeners, restores free camera input, starts the hero and publishes a static-tier notice (`main.js:1256-1269`); temporary warm render targets and scene visibility mutations are restored in `finally` (`journey/journey.js:1518-1555`). A malformed version-1 bake manifest was runtime-reproduced to reach fallback (`.oracle/findings/wave1/wave1-L7.txt:3-4`; `wave1-L9.txt:3-4`).

The failure is not transactional, however. By the time `state.ready` can fail or stall, chapters have already attached groups/animators, `boot()` has replaced `setView`, scroll has attached global listeners, and UI/rail have attached DOM/document listeners. The catch path cleans only the intro capture and input policy. It neither undoes construction nor clears `started`, `journeyLoadP`, prepared chapters, lens ownership, UI, or animators (`main.js:1256-1272`; `journey/journey.js:123-131,164-190,204-273`). This matters for fallback resource use now, and becomes a correctness hazard if retry/recreate is ever attempted.

## Verified risks

“Verified” below means the behavior is directly established in source; where Wave 1 performed a browser reproduction, that is stated separately. Reproduction is still required before fixing source-only visitor impact, per the plan's evidence rule.

1. **P0 — preparation has no terminal time bound.** Baked manifest/bin fetches have no abort/deadline (`journey/lib/baked.js:75-99`) and are awaited before construction (`main.js:1222-1227`). The portrait sprite is a bare `Image` promise (`journey/chapters/owned/portrait-photo-loader.js:3-10`) and is awaited by GPU preparation (`journey/journey.js:1495-1504`); `compileAsync` also has no deadline. Only the later fence polling is bounded at eight seconds (`journey/journey.js:1454-1479`). A never-settling request leaves `scene-preparing`, journey input capture, and disabled orbit in place indefinitely, with no static link. This is the common high finding from Wave 1 L1/L3/L4 (`wave1-L1.txt:3-4`; `wave1-L3.txt:3-4`; `wave1-L4.txt:1-2`), although all three correctly note the missing controlled hang reproduction.

2. **P0/P1 — intro acceleration permanently corrupts a realm-global clock contract.** `accelerate()` assigns `performance.now` and never restores it (`organism/intro.js:208-225`). Wave 1's live probe measured the difference between `performance.now()` and the RAF timestamp jumping from 22.7 ms to 8,504 ms after one wheel (`wave1-L7.txt:5-6`). The code already has to compensate by preferring event timestamps during early input (`main.js:1002-1007`), while browser probes and film/input tooling also use `performance.now` (`tools/scrollprobe.js:123-169`; `tools/film/film.py:69-71`). This is non-local mutable state with observable cross-subsystem consequences.

3. **P1 — context loss is handled visually but not as a rendering lifecycle.** The context handlers only schedule/clear a note (`main.js:320-336`); the RAF schedules itself unconditionally before rendering (`organism/animation.js:13-38`). Wave 1 measured 181 composer renders during three seconds of forced context loss (`wave1-L6.txt:9-10`). Repeated loss overwrites a single timer, so `loss → loss → restore` clears only the newest handle and an older fallback can still appear; Wave 1 reproduced that synthetic sequence (`wave1-L7.txt:11-12`). Context loss/restoration is explicitly supported by source, so pausing work and coalescing recovery are required even though general scene recreation is not.

4. **P1 — boot/fallback is latched, non-transactional, and unable to retry safely.** `started = true` precedes even the scene-handle check (`journey/journey.js:123-131`); prepared chapters are module-global, scene-unkeyed, and never reset (`journey/chapter-registry.js:22-41`); the lens is likewise a scene-unkeyed singleton (`journey/lens.js:288-304`); and the director replaces `sceneApi.setView` without restoration (`journey/director.js:202-218`). Wave 1 consistently identified this ownership cluster (`wave1-L1.txt:7-11`; `wave1-L3.txt:5-8`; `wave1-L4.txt:5-6`). In the normal one-shot path, the singleton lens and prepared registry preserve frame order and avoid visible grade/build hitches. Across failure/retry or a second scene, they point at the first scene and are dangerous.

5. **P1 — a persistent render failure has neither containment nor visitor fallback.** Animator callbacks are individually disabled after their first exception, but `beforeRender()` and `render()` execute outside that guard and after the next RAF has already been scheduled (`organism/animation.js:17-36`). A persistent composer/render failure therefore continues scheduling failing frames, while the global handler merely counts/logs errors unless a QA overlay flag is active (`main.js:64-87`). Wave 1 L1 identified the missing post-boot recovery (`wave1-L1.txt:5-6`); the injected-renderer reproduction remains open.

6. **P1 — incomplete markup can abort before the fallback authority is published.** Hero callout elements and their `.tag` descendants are dereferenced without checks (`main.js:811-869`), while `window.sceneApi` is published only afterward (`main.js:911-916`). The scene RAF has already started, but the page-level module aborts and no visitor fallback is installed. Wave 1 L1 records the same source finding and the required markup-fault probe (`wave1-L1.txt:9-10`).

7. **P1/P2 — failure isolation is silent and permanent within a visit.** Both the organism animator registry and journey failure guard remove a named subsystem after one exception and only log (`organism/animation.js:24-31`; `journey/failure-guard.js:1-10`). This is preferable to taking down the full ride, but handled failures do not reach the visitor-facing fallback or the global error counter. Wave 1 L9 established the UI path and its observability gap (`wave1-L9.txt:7-8`). Whether each subsystem failure warrants a visible degraded-state signal is product-visible and must be probed, not assumed.

## Harmless page-lifetime behavior versus candidates

### Harmless under the evidenced one-document/one-instance contract

- Permanent hero, journey, UI and rail listeners do not alone prove a leak. Their closures die with the document, and the live entry has one top-level `createScene()` and one `loadJourney()` call (`main.js:302-313,1174-1176,1289-1292`). Adding dozens of detach methods without a supported caller would be score-chasing.
- Card-local timers and media are generally bounded on deactivation. Discord clears cycling/swap timers (`journey/cards/discord.js:443-453`); ADOS cancels its pending swap, pauses video, drops `src`, and calls `load()` (`journey/cards/ados.js:248-260`); Arca pauses videos (`journey/cards/arca.js:60-74`). Wave 1 L3/L6 explicitly found no active card-timer/media leak (`wave1-L3.txt:9`; `wave1-L6.txt:15`).
- Portrait late success is guarded by `disposed`, and texture disposal is idempotent (`journey/chapters/owned/portraits.js:1858-1879,2017-2037`). The current defect is the unbounded readiness wait and absence of a caller for disposal, not an observed late texture mutation.
- Discord's remote request has a four-second `AbortController` deadline (`journey/cards/discord.js:124-138`); preparation stores snapshots and does not replace visible fallback content with late live data (`journey/cards/discord.js:188-223`). Its module cache is coherent for the one cached stage per node (`journey/ui.js:379-426`).
- The Ownership page's visibility-aware RAF behavior is bounded as described above. Its page-lifetime listeners are not coupled to the live journey.

### Candidates requiring targeted evidence

1. **TAA restore corruption.** `validHistory` resets only on `setSize()` (`organism/organism.js:120-165`), while restoration does not invalidate or rewarm it (`main.js:327-335`). A flash/smear is plausible, not yet pixel-verified (`wave1-L4.txt:3-4`).
2. **Fallback residual work.** A readiness failure after `boot()` leaves disabled scroll listeners, UI/rail document listeners, chapter animators/groups, the director patch, and cached DOM alive behind the hero fallback. Source ownership proves retention; CPU/memory/user impact and which failure phases reach it still need fault injection.
3. **Same-document recreate leaks/cross-wiring.** Two scenes would create two perpetual RAFs and reuse first-scene lens/chapters, but there is no production caller. Run the isolation probe to choose a contract; do not pre-commit to universal disposal.
4. **Uncancelled surplus warming.** The card warmer recursively schedules every asset fetch without storing idle handles or fetch controllers (`journey/cards/index.js:92-113`), matching Wave 1 L9's source finding (`wave1-L9.txt:9-10`). Network contention after an immediate hover, hidden-tab entry, fallback, or navigation is unmeasured. This is performance/priority debt, not yet a correctness defect.
5. **Final/scene disposal completeness.** The owned portrait and Final ring possess local disposers, but they are not composed upward; renderer, controls, composer/passes, DOM, listeners and scene resources have no aggregate boundary. This becomes a verified defect only if rollback/recreate is accepted or resource counts remain elevated after a supported transition.
6. **Late detail/UI timers.** Deep-link detail opening is a bare delayed task (`journey/journey.js:1296-1310`), and UI/rail have many closure timers with no destroy boundary. They are short and harmless in the normal instance; a rollback/recreate probe should determine whether they mutate abandoned DOM.

## Non-local ownership that changes must not accidentally preserve

- `window.sceneApi` is an intentional composition bridge, but boot reads it rather than receiving it (`main.js:911-916`; `journey/journey.js:123-130`). `window.journey` is both a QA/public handle and a hidden runtime dependency: UI repeatedly resolves chapter policies and selection through it (`journey/ui.js:803-818,1571-1589`). This couples publication timing to UI correctness.
- `preparedChapters`, `_lens`, `started`, baked `manifest`/`bins`, and card promises/snapshots are module-cache ownership. They are coherent only while scene and document lifetimes coincide (`journey/chapter-registry.js:22-41`; `journey/lens.js:300-304`; `journey/journey.js:106,123-125`; `journey/lib/baked.js:55-57`; `journey/cards/discord.js:37-47`).
- `sceneApi.setView` is shared mutable authority replaced in place by the director (`journey/director.js:202-218`). Responsive bootstrap still calls this shared method (`main.js:703-737`). Any rollback or ownership move must preserve the existing defer/replay behavior and restore the exact prior function.
- `window.__pageErrors`, `window.__bake`, and `window.__tkPerf`-style values are deliberate QA/build outputs (`main.js:64-86`; `journey/lib/baked.js:154-165`; `organism/spores.js:1039-1045`). They should be documented/tested as diagnostics, not mistaken for application state. Replacing `performance.now` is qualitatively different: it mutates a platform global consumed outside its owner.

## Lifecycle invariants to characterize before change

1. **Supported lifetime:** exactly one live hero RAF and one journey instance per document. A second `loadJourney()` is idempotent. Decide explicitly whether a second `createScene`/failed-boot retry is rejected or supported; only the supported branch needs full recreate semantics.
2. **Startup terminality:** every import/fetch/image/compile/driver outcome reaches exactly one terminal state within a declared budget: interactive journey or a visible, keyboard-reachable static fallback. `scene-preparing` and intro-capture listeners cannot survive terminal fallback.
3. **No late activation:** once fallback/abort wins, releasing a held fetch/image/compile promise must not publish `window.journey`, enable scroll, alter input policy, or mutate discarded DOM/resources. This requires a generation/abort contract if time bounds are added.
4. **Transactional failure:** faulting each preparation phase leaves animator names, scene children, global listener counts, document nodes, renderer resources and `setView` identity at the declared fallback baseline. If retry is supported, retry starts from fresh scene-keyed state; if not, the second call fails explicitly and harmlessly.
5. **Frame order:** the reserved `journey` slot remains before lens and all chapter animators; spine writes scroll/state/camera before chapter/lens readers (`main.js:350-359`; `journey/journey.js:143-164,1262-1270`). Lifecycle cleanup must not delete/reinsert it in a different order.
6. **Context loss:** no composer submissions while lost; multiple loss events coalesce to one deadline; restoration cancels all stale notices, resizes/revalidates targets, invalidates TAA history, and resumes one RAF. Several restored frames must match a fresh-load reference within the established capture tolerance.
7. **Clock integrity:** outside an explicit test harness, `performance.now()` remains the native function and stays close to RAF/event timestamps before, during, and after intro acceleration. Intro and all other animation outcomes remain visually equivalent using an owner-local clock.
8. **Local activation:** closing/switching every card stops its timers/media immediately; late fallback/live/image settlement does not render into a hidden or detached stage. Reopening is deterministic and starts at the documented state.
9. **Resource stability:** across every *supported* repeated transition (card open/close, chapter enter/leave, hide/show, context loss/restore, and retry only if accepted), RAF/listener/timer counts and WebGL resource counts return to a stable plateau. Do not assert universal zero at page lifetime.
10. **Failure observability:** an isolated animator/UI/chapter fault is reported once with subsystem identity; the remaining page still works. A core render failure produces a visitor-safe fallback rather than an endless exception loop.

Current automated coverage does not characterize these contracts: `npm test` runs scroll, connect, chapter-entry, static-content and browser-smoke gates only (`package.json:9-13`), and repository search finds no context-loss, disposal, retry, or listener/RAF-count scenario.

## Prioritized targeted Luna probes

1. **P0 — bounded-startup/late-settlement matrix.** Independently hold the journey import, manifest, one bin, portrait sprite, `compileAsync`, and GPU fence. Exercise no input plus early wheel/touch/CTA. Record body classes, fallback accessibility, input policy, listener/RAF/animator counts, and then release the held operation to prove no late activation after fallback. This adjudicates the shared L1/L3/L4 high finding.
2. **P0 — fault-by-phase transactional boot.** Throw after each chapter construction, director patch, scroll attach, UI construction, portrait preparation, compile, warm draw and drain. Compare scene children, animator `Map`, document `.j-*` nodes, listeners/timers and `sceneApi.setView` before/after fallback. Then call `boot()`/`loadJourney()` again to decide explicitly between terminal one-shot failure and supported retry.
3. **P0 — partial-markup bootstrap.** Remove each required callout/container/tag one at a time before load. Require a useful live or static tier, a visible note, no uncaught-frame storm, and no orphan scene hidden behind `scene-preparing`.
4. **P1 — context-loss contract.** With `WEBGL_lose_context`, count composer calls during a sustained loss; run `loss → loss → restore`; inspect all pending timers, RAF count, render-target sizes and TAA validity; compare the first several restored frames with a fresh load on desktop and mobile/Safari-capable infrastructure.
5. **P1 — instance-isolation decision probe.** Prepare chapters on scene A, build/boot against scene B, and inspect group parents, animator ownership, lens composer, `setView`, listeners and resource counts. If production remains one-shot, encode rejection/idempotence and rollback rather than building general multi-instance machinery. If recreation is required, this becomes the disposer/reset acceptance suite.
6. **P1 — global-clock contract.** Trigger acceleration and continuously sample native RAF timestamp, event timestamp, `performance.now`, Three clock `dt`, input timing and QA tooling. Preserve the current visual fast-forward while proving no global offset survives the ramp.
7. **P1 — post-boot failure behavior.** Inject one-shot and persistent throws into an ordinary animator, `ui.update`, `beforeRender`, composer render, and a chapter callback. Verify once-only diagnostics, subsystem containment where possible, static fallback for core rendering, and absence of repeated exceptions/work.
8. **P2 — card/portrait late-settlement contracts.** Under fake clocks and controlled fetch/Image, deactivate or dispose before success/failure, then settle. Assert no detached-DOM mutation, no restarted timer/media, correct cached reopen, portrait texture stability, and cancellation/priority behavior for surplus warming.
9. **P2 — Ownership visibility loop.** Count RAFs over repeated hide/show/resize cycles and reduced-motion loads. Expect zero hidden, at most one active loop per role when visible, and no growth restart after completion.

The simplest evidence-led direction is therefore: first make startup and context-loss terminal and observable; remove the global clock mutation; then choose and encode the one-shot-versus-recreate contract. Only after that choice should disposal be composed upward, and only to the boundary the tests demonstrate.
